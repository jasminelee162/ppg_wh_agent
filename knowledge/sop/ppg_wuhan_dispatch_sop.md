# PPG 芜湖仓发运 SOP

## 文档信息
- 适用范围：PPG 芜湖仓库（马鞍山库）日常发运作业
- 系统支持：ppg_wh_agent 自动化邮件解析与飞书多维表同步

---

## 一、日常发运流程

### 1.1 订单接收
1. 系统每日自动拉取 IMAP 邮件（`ppgwh-auto@efs.com.cn`）
2. 识别 PDF 发货单附件（`PDF_ORDER` 类型邮件）
3. 解析以下关键字段：
   - 订单号（格式：`11XXXXXXX`，8-9 位数字）
   - 收货地址、收货人、联系电话
   - 货物重量（KG）、数量（桶/箱）
   - 下单日期

### 1.2 发运方式确认
优先级从高到低：
1. **发货单 PDF 内明确标注**（最高优先级）
2. **wenjuan 邮件通知**（无正文 + PDF 附件 + 标题含关键词）
3. **SHIPPING_INFO 邮件正文**（其他发件人）
4. **RAG 知识库推断**（以上均无时，作为参考提示）
5. **默认值**：零担

关键词映射：
| 邮件关键词 | 系统字段值 |
|-----------|----------|
| 保温车 | 保温车 |
| 包车、整车 | 包车 |
| 零担、拼车 | 零担 |
| 自提、自取 | 自提 |

### 1.3 危险品确认
1. 系统自动从 PDF 识别危险品类别（`pdf_danger` 字段）
2. 若 PDF 未标注，从发运缓存（`shipping_all.json`）补充
3. 可结合 RAG 知识库对产品描述进行辅助判断

危险品类别标准值：
- `DG`（危险品）
- `NDG`（普通货物）
- 具体类别：`第3类`、`第6.1类`、`第8类`、`第9类`

### 1.4 地址规范化
系统自动进行：
1. 提取中文地址（过滤订单号、电话、英文）
2. 精确匹配收货单位（`business/constants/receivers.py`）
3. 模糊匹配（Levenshtein 距离）
4. 使用 jionlp NLP 提取省市信息

### 1.5 写入飞书多维表
字段映射：
| 飞书字段 | 系统字段 |
|---------|---------|
| 客户名 | 固定值：芜湖PPG |
| 单号 | order_no |
| 订单状态 | sync_status 映射 |
| 下单日期 | order_date（Unix ms）|
| 收货单位 | receiver |
| 收货地址 | address |
| 收货人 | contact |
| 数量 | quantity |
| 重量 | weight |
| 发运方式 | 发运方式 |
| 始发城市 | 固定值：马鞍山库 |
| 到货城市 | 到货城市 |
| 到货省份 | 到货省份 |
| 产品特性 | 危险品类别（DG/NDG）|

## 二、特殊业务指令处理

### 2.1 取消订单
触发条件（邮件正文含以下关键词）：
- 停止、作废、不用发、取消

处理逻辑：
1. 从正文/标题提取订单号（`11XXXXXXX` 格式）
2. 将暂存区对应订单 `sync_status` 改为 `已取消`
3. 通知飞书多维表更新状态字段为"已取消"

### 2.2 改单（更新订单）
触发条件（邮件正文含以下关键词）：
- 更新、以此为准、重新提供

处理逻辑：
1. 解析最新 PDF 发货单
2. 用新字段覆盖暂存区，`sync_status` 改为 `已更新`
3. 通知飞书多维表覆盖对应行

### 2.3 拆单
触发条件：
- 正文或标题含"拆"，且附件 ≥ 2 个 PDF

处理逻辑：
1. 第一个 PDF → 原单（`已更新`）
2. 第二个 PDF → 子单（`拆单`），若订单号同原单则后缀 `-1`
3. 两个订单均写入飞书多维表

## 三、异常处理规范

### 3.1 无法解析日期
- 现象：`order_date` 为空或格式无法识别
- 处理：订单标记为 `anomaly`，跳过本次同步，等待人工确认

### 3.2 订单号非法
- 现象：解析出的订单号不符合 `11XXXXXXX` 格式（前两位非11，位数不对）
- 处理：跳过该 PDF，记录日志警告

### 3.3 地址模糊匹配
- 现象：`address_exact_match = 模糊匹配`
- 处理：飞书记录地址状态为"模糊匹配"，需人工核实

### 3.4 发运方式/危险品均未识别
- 现象：`发运方式` 为空，`危险品类别` 为空
- 处理：
  1. 系统调用 RAG 知识库返回推断提示（`_rag_hint` 字段）
  2. 运营人员根据提示确认后手动填写飞书

## 五、数据文件说明

| 文件路径 | 说明 | 更新方式 |
|---------|------|---------|
| `output/cache/shipping_all.json` | 全量发运缓存，订单号→发运方式/危险品 | 邮件解析时自动累积 |
| `output/cache/pending_orders.json` | 暂存区，所有状态订单 | 邮件解析时写入，同步后标 synced |
| `output/cache/seen_mails.json` | 已处理邮件 UID | 每次运行后追加 |
| `output/orders_YYYY-MM-DD.json` | 每日同步输出 | sync_orders.py 生成 |
| `output/rag_index/` | 向量索引持久化目录 | 执行 build_index.py 时生成 |

## 六、RAG 知识库使用说明

### 构建索引（首次 / 知识更新后执行）
```bash
python rag/build_index.py
```

### 查询示例
```python
from rag.rag_pipeline import RAGPipeline

rag = RAGPipeline()

# 查询运输方式
result = rag.query("冬季溶剂型涂料发运，需要温控", category="transport_modes", top_k=3)

# 查询危险品规则
result = rag.query("UN1263 油漆运输要求", category="goods_classification", top_k=3)

# 对订单进行综合解释
hints = rag.explain(order_dict)
```

### 知识文档更新方法
1. 修改 `knowledge/` 目录下对应 Markdown 文件
2. 重新运行 `python rag/build_index.py` 重建索引
3. 无需修改任何业务代码
